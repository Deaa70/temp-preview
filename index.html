What I noticed in the retrieval code

  • The rewrite now controls retrieval. The fallback to your original question only fires if the classifier call throws, not when it returns a bad rewrite. Spot-check rewrites on real student questions. The no_ai_chunks_found message is unused now; reuse it in the QA and Summary zero-hit paths if you want it.
  • Pro QA skips the nearest neighbors. section_order__in=[order-2, order+2] fetches only those two positions, not ±1 and ±2. Pro gets distant sections and loses the adjacent ones. A range filter fixes it.
  • "No chunks" almost never triggers. RRF returns something whenever the filter matches any chunk, and its score reflects rank, not relevance. A re-ranker gives a score you can threshold, so a weak top hit can lead to "I don't know" instead of a confident wrong answer.
  • Exam questions lose their ranking. The IDs are ordered by score, but the DB query returns them in its own order, so the "top 3" are the right 3 in arbitrary order. EXAM_PREP does this correctly with a map.
  • Agent loop check is a substring match. "SUFFICIENT" in response also matches "INSUFFICIENT", if your prompt ever uses that word.
  • Open decision for Pro (top 3). Neighbors for all 3 chunks can blow up the context; neighbors for the rank-1 chunk only is the cheaper start.
